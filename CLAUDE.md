# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kinolog is a personal film & book index built over Letterboxd and Goodreads exports. It is a learning project for vector databases, chunking strategies, retrieval evaluation, and RAG/agent loops, so retrieval changes are expected to be measured with the eval harness rather than judged by eye.

## Commands

The package lives in `src/kinolog/` and is imported as `kinolog.*`. Install it first with `pip install -e '.[dev,web,mcp]'` (tests import the installed package; there is no `pythonpath` hack). Run commands from the repo root: the default paths (`data/index.db`, `data/cache/...`) are relative to the working directory. `kinolog <command>` and `python -m kinolog <command>` are equivalent to `python3 -m kinolog.interfaces.cli <command>`.

```bash
.venv/bin/pytest -v                                   # full suite (fast, in-memory SQLite)
.venv/bin/pytest tests/retrieval/test_search.py::test_bm25_search  # single test
ruff check src tests                                  # lint (dev extra; not installed in .venv by default)

python3 -m kinolog.interfaces.cli stats
python3 -m kinolog.interfaces.cli ingest letterboxd data/raw_exports/letterboxd
python3 -m kinolog.interfaces.cli ingest resolve          # needs TMDB_API_KEY
python3 -m kinolog.interfaces.cli ingest review           # interactive match queue
python3 -m kinolog.interfaces.cli ingest enrich
python3 -m kinolog.interfaces.cli ingest omdb --max-requests 1000  # ratings; needs OMDB_API_KEY
python3 -m kinolog.interfaces.cli ingest chunk --strategy whole
python3 -m kinolog.interfaces.cli ingest embed --model bge_m3 --strategy whole
python3 -m kinolog.interfaces.cli search "journalist in Rome" --mode rrf
python3 -m kinolog.interfaces.cli eval known-items --mode bm25
python3 -m kinolog.interfaces.cli eval hearts --ranker nearest_exemplar --splits 10
python3 -m kinolog.interfaces.mcp                         # stdio MCP server (needs `mcp` extra)
npm --prefix frontend ci && npm --prefix frontend run build  # build the web UI (once, and after frontend changes)
python3 -m kinolog.interfaces.web --db data/index.db      # local web UI (needs `web` extra)
npm --prefix frontend run dev      # UI dev server on 127.0.0.1:5173, proxies /api to :8765
npm --prefix frontend run typecheck && npm --prefix frontend test  # frontend checks (Vitest)
npm --prefix frontend run lint     # oxlint (config: frontend/.oxlintrc.json; warnings only for now)
python3 -m kinolog.interfaces.cli eval concierge --hearts # concierge eval
python3 -m kinolog.interfaces.cli ingest backfill-runtime # runtime_min / is_tv / imdb_id from stored TMDB data
```

Every CLI command accepts `--db` (default `data/index.db`) and `-v`. The CLI is plain argparse in `src/kinolog/interfaces/cli/` (`main.py` builds the parser and dispatches; handlers live in `ingest.py`, `query.py`, `eval.py`, `review.py`; click/rich are only used for table output in `output.py` when installed). Handlers stay thin: parse arguments, call `kinolog.pipeline` (ingest) or `kinolog.services` (queries), print. Adding a command means adding a subparser in `build_parser`, a `handle_*` function in the matching module, and a dispatch branch in `run_argparse_cli`.

## Architecture

**Pipeline:** sources (load, resolve, enrich) → documents → chunks → embeddings → retrieval / taste → rag / features → services → interfaces. Each ingest stage is a separate CLI step (`kinolog.pipeline` has them as plain functions) and is idempotent, so stages can be re-run independently.

```
src/kinolog/
├── config.py  domain.py        # layer 0: default paths/names; shared dataclasses and constants
├── store/                      # layer 1: Database facade from per-aggregate mixins, migrations/
├── sources/                    # layer 2: letterboxd/ goodreads/ tmdb/ openlibrary/ wikipedia/ subtitles/
├── index/                      # layer 2: chunking/ embedding/ (strategy registries)
├── retrieval/                  # layer 3: bm25, vector, fusion, search dispatcher, filters
├── rag/                        # layer 4: context assembly, grounding checks, chat agent, LLM generator
├── taste/                      # layer 4: ranker registry, scores, TasteCache
├── features/                   # layer 5: concierge/, collections, crew, docfacts
├── pipeline.py  services.py    # layer 6: ingest steps; logic shared by CLI, MCP and web
├── eval/                       # layer 7: metrics, runner, suites/, datasets/
└── interfaces/                 # layer 8: cli/ mcp/ web/   (`__main__.py` sits above)
frontend/                       # Vite + React + TypeScript, builds into interfaces/web/dist
tests/                          # mirrors src/kinolog, plus test_layering.py
```

**Layering** is enforced by `tests/test_layering.py`, which walks every import (including lazy ones inside functions): a module may import its own top-level package or a strictly lower layer, never a sibling package at the same layer or a higher one. New top-level packages must be added to `LAYERS` there. The same file enforces that only `kinolog.store` writes to the database (no INSERT/UPDATE/DELETE/REPLACE string outside it); sources and the index runner call named methods such as `set_match`, `mark_queued`, `set_item_facts`, `set_wikidata_id_if_missing` and `upsert_embedding`. Read queries may live in the module whose subject they are (BM25 SQL in `retrieval`, aggregation SQL in `features/collections.py`).

**Config and domain.** `config.py` holds every default path (`data/index.db`, `data/cache/<source>/`, `.env`) and the default model/strategy/ranker names; `domain.py` holds `Chunk` and `SHORT_MAX_MIN`. Both sit below everything else and import nothing from the package.

- **Store** (`src/kinolog/store/`): the single `Database` class (`store/database.py`) is assembled from one mixin per aggregate (`items.py`, `documents.py`, `people.py`, `ingest_meta.py`, `user_state.py`, `views.py`, `eval_runs.py`, `vectors.py`) over `connection.py`; import it as `from kinolog.store import Database`. The schema evolves through numbered migrations in `store/migrations/` (`mNNN_name.sql` or `mNNN_name.py` with `upgrade(conn)`), applied on construction and tracked with `PRAGMA user_version`. To change the schema add a new numbered file; never edit an applied migration. Migrations 001 to 003 are idempotent because databases created before migrations existed report `user_version = 0` but already have everything; later ones may assume the previous state. Per-model `vec_<model>` tables are created on demand, not by migrations. Key relationships: `items` (films and books share one table, discriminated by `item_type`) → `documents` (one per item/source/lang) → `chunks` (one row per document/strategy/ord). `user_status` holds seen/watchlist/liked state; `people`/`credits` hold TMDB crew. All upserts are content-hash based and skip unchanged text. Only `kinolog.store` writes to the database (no INSERT/UPDATE/DELETE/REPLACE string outside it; `tests/test_layering.py` enforces this): sources and the index runner call named methods such as `set_match`, `mark_queued`, `set_item_facts`, `set_wikidata_id_if_missing`, `upsert_embedding`. Read queries may live in the module whose subject they are.
- **FTS5** `chunks_fts` is an external-content table kept in sync by triggers on `chunks` — never write to it directly.
- **Vectors**: `sqlite-vec` is optional. Each embedding model gets its own `vec0` table named `vec_<model_name>` (e.g. `vec_bge_m3`, 1024-dim; `multilingual_e5`, 768-dim, uses `query: `/`passage: ` prefixes). When the extension fails to load, `db.vec_available` is False and vector search returns `[]` instead of raising — keep that graceful-degradation behavior.
- **Chunking strategies** (`src/kinolog/index/chunking/`, registry `STRATEGIES` in `base.py`, one module per variant registered with `@register(name)`): `whole`, `fixed_256_50`, `fixed_512_100`, `section`, `section_no_prefix`; `runner.py` has `chunk_document`/`chunk_all_documents`. The strategy name is stored on each chunk, and embeddings/search are always scoped to one strategy, so multiple strategies coexist in the DB for comparison. Embedding models follow the same pattern in `index/embedding/` (`EMBEDDERS`: `bge_m3`, `multilingual_e5`). To add a variant, add a module and import it in the package `__init__`.
- **Retrieval** (`src/kinolog/retrieval/`: `bm25.py`, `vector.py`, `fusion.py`, `search.py` dispatcher, `filters.py`, `results.py`): `search_bm25`, `search_vector`, `search_rrf` (reciprocal rank fusion), plus a `search()` dispatcher by mode. Results are deduped to one per item. `SearchFilters` builds SQL conditions for item type/decade and `user_status` joins.
- **Taste** (`src/kinolog/taste/`): the `RANKERS` registry (`base.py`) with one module per ranker family (`mean.py`, `exemplar.py`, `prototypes.py`) over `data.py` and `scores.py` (`taste_scores`, `taste_available`, `TasteUnavailableError`). Rankers score unseen/watchlist candidates by similarity to hearted ("liked") item embeddings: `mean_heart`, `nearest_exemplar`, `top_3_mean`, `prototypes_4..6` (k-means). `cache.py` has `TasteCache`, owned by the web `AppState`. Letterboxd likes are dated; `first_heart_date` restricts the Positive-Unlabeled evaluation to candidates seen after hearts started being used.
- **Sources** (`src/kinolog/sources/`, one folder per external system): `letterboxd/load.py` and `goodreads/load.py` load exports; `tmdb/` (`client.py` HTTP + disk cache, `resolve.py` matching: multi-language, year drift ±1/±2, alt titles, `enrich.py` metadata/credits/documents), `openlibrary/` (`client.py`, `resolve.py`), `wikipedia/` (`client.py` Wikidata sitelinks + sections, `enrich.py`, EN/FR/IT) and `omdb/` (`client.py`, `enrich.py`: IMDb / Rotten Tomatoes / Metacritic scores keyed by the `items.imdb_id` that TMDB supplies) and `subtitles/` (`parse.py` SRT parsing and scene chunks with `start_ms`/`end_ms`, `enrich.py` loading). Low-confidence matches go to `match_review_queue` and are resolved via `interfaces/cli/review.py`. External API responses are disk-cached under `data/cache/<source>/` (file names are an on-disk contract; `sources/http_cache.py` holds the shared JSON read/write/fetch helpers) and tracked in `raw_cache`. `src/kinolog/pipeline.py` has the ingest steps as plain functions (`load_letterboxd`, `resolve`, `enrich`, `backfill_runtime`, `chunk`, `embed`) that the CLI and the web import route call. TMDB is the metadata master and also supplies `items.imdb_id`; the OMDb enricher fetches scores into `external_ratings` (one row per item/source, `score` normalized 0..100, `raw` string, IMDb `votes`; table and column come from migration 004). Ratings are never written to `documents`, so they stay out of retrieval. Item cards (`get_item_cards`) carry them as `external_ratings`; the UI's `ExternalRatings` component shows them on watchlist rows, concierge picks and the Log table (Scores column). OMDb's free tier is 1,000 requests/day: only definitive answers are cached, `--max-requests` caps a run, and a "Request limit reached" answer (or 3 transport/server failures in a row) defers the rest to the next run. IMDb ids already checked (a `raw_cache` row with source `omdb`, whether or not they had scores) are skipped unless `--refresh`. Re-matching or rejecting an item in review clears its `imdb_id`, ratings and that marker. The OMDb client sets the `httpx` logger to WARNING because request URLs carry the API key. `apply_details_columns` in `sources/tmdb/enrich.py` is the one place TMDB details become item columns (enrichment overwrites; the offline `ingest backfill-runtime` cache backfill only fills empty columns).
- **RAG** (`src/kinolog/rag/`): `context.py` assembles retrieved chunks under a token budget with numbered `[^n]` citations; `grounding.py` has `groundedness`, `MentionScope` and `check_grounding` (one definition of "is this answer supported by what we retrieved?", shared by the chat agent and the Concierge); `agent.py` is the chat agent (`answer_query` accepts pre-fetched `results`, `filters` and a `mention_scope`, and reports invalid `[^n]` citations); `llm.py` builds the optional LLM generator (`llm` extra).
- **Services** (`src/kinolog/services.py`): the logic the interfaces share (`search_items`, `similar_to`, `rank_watchlist`, `filmography`, `crew_overlap`, `stats`, `watchlist_view`, `add_to_watchlist`/`remove_from_watchlist`/`log_as_watched`, `directors_view`/`director_view`, `concierge_*`, ...). They take a `Database` (plus a model provider, `taste_fn` or rerank weights) and return plain dicts; they never raise `HTTPException` or take `db_lock`. Domain errors (`NotFoundError`, `InvalidInputError`, `UnavailableError`, `TasteUnavailableError`) propagate and each interface maps them (web: 404/422/409; MCP: `{"error": ...}`). Taste cache invalidation after writes stays in the web layer.
- **Eval** (`src/kinolog/eval/`): `runner.py` has `EvalResult` and `log_results` (results are written to the `eval_runs` table); suites live in `suites/`: `known_items.py` (known-item retrieval, `datasets/known_items.json`, Hit@k/MRR), `hearts.py` (multi-split Recall@20/50, MRR with stdev), `concierge.py`, `adaptation.py` (book↔film cross-modal retrieval), `faithfulness.py` (`datasets/faithfulness_prompts.json`, groundedness/citations) and `vector_stores.py` (store benchmarks); shared metrics are in `metrics.py`. Datasets are loaded with `importlib.resources`, so they work from any working directory.
- **Interfaces** (`src/kinolog/interfaces/`): `cli/` (see Commands), `mcp/` (`tools.py` has the `TOOLS` schemas, `server.py` the `KinologServer.handle_tool` dispatcher over the services, so tool logic is testable without the `mcp` package; tools: `search`, `rank_watchlist`, `similar_to`, `filmography`, `crew_overlap`, `stats`) and `web/`.
- **Web UI** (`src/kinolog/interfaces/web/`): FastAPI app factory `create_app(db, load_model=..., generator=...)`, routes under `routes/`, Vite + React + TypeScript frontend under `frontend/` (strict TS, hand-written payload types in `src/types.ts`, hash routes, no router/query libraries, no CDN or external requests; Tailwind CSS v4 via `@tailwindcss/vite` (build-time only); UI primitives are shadcn/ui components copied into `src/components/ui/` (Radix via `radix-ui`, cva, tailwind-merge `cn` in `src/lib/utils.ts`, lucide-react icons, sonner toasts), imported through the `@/` alias (`@/*` -> `src/*`); the shadcn theme variables are mapped onto the Kinolog palette in `frontend/src/styles/tokens.css` (light only; shadcn `accent` is a hover wash, Kinolog's terracotta is `brand`); layout class strings live in `src/components/styles.ts`; `Modal` (Dialog wrapper), `Segmented` (ToggleGroup, `''` mapped to a sentinel), `RatingSelect` (Select, `"none"` sentinel) and `useToast` (sonner) keep their old APIs; Radix Dialog has no Trigger here, so `Modal` restores focus to the opener itself). The build goes to the gitignored `web/dist/`, which FastAPI serves (`/` returns a 503 with the build hint when it is missing); Node is needed to build it. One SQLite connection is shared across threads (`Database(..., check_same_thread=False)`), so all DB access goes through `AppState.db_lock`. Routes stay thin and call `kinolog.services`; core logic lives outside the web package: `src/kinolog/features/collections.py` (director completion; shorts <= 40 min and `is_tv` excluded, index-only denominator), `src/kinolog/features/concierge/` (`constraints.py` parser, `rationale.py`, `pick.py`), `src/kinolog/features/docfacts.py`. Web tests live in `tests/web/` and skip without the `web` extra.
- **User actions and re-import**: UI writes go through `Database` methods (`set_watchlist`, `log_watch`, `update_watch`, `delete_watch`, `set_rating`, `set_liked`). `watch_log` rows are idempotent by `(source, source_key)`, deletes are tombstones, edited rows are protected, and `user_status.manual_updated_at` / `watchlist_removed_at` stop Letterboxd re-imports from overwriting manual changes. Ratings are half-stars stored as integers 1..10.
- **Concierge**: constraint phrases ("90 minutes", "60s", "haven't seen") become SQL filters and are stripped from the retrieval text; rationales are built from cited chunks and structured facts, and LLM output (optional, `llm` extra) is accepted only if grounded and all citations resolve. Rerank weights `w_taste`/`w_comp` default to 0 until `eval concierge` shows a gain beyond the split stdev.

## Conventions

- `tests/` mirrors the package (`tests/store`, `sources`, `index`, `retrieval`, `rag`, `taste`, `features`, `eval`, `interfaces`, `interfaces/web`), with `test_layering.py`, `test_registries.py` and `test_services.py` at the top. Every test folder has an `__init__.py` (so equal basenames in different folders do not clash). `tests/conftest.py` provides an in-memory `db` fixture and `make_film` / `make_document` factories.
- Tests build fixtures against `Database(":memory:")` with hand-inserted items/documents; none of them call external APIs or load embedding models, which keeps the suite under a second.
- `data/raw_exports/`, `data/cache/`, and `data/*.db` are gitignored personal data — don't commit them.
- Ruff: line length 100, target py311, rules `E,F,I,N,W,UP`.
